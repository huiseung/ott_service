# Admin HLS preview

The admin web authenticates `POST /api/admin/videos/{id}/preview` and HLS manifest GETs with HTTP Basic. The master manifest points to an authenticated variant manifest. The variant manifest contains short-lived, object-specific signed GET URLs for segments. The browser downloads segments from object storage; neither the admin API nor Next.js carries segment bytes. The admin player reloads the manifests before the configured 15-minute URL lifetime ends, keeping the current position.

The bucket remains private. An unsigned segment GET returns 403. A signed URL is a bearer credential: anyone who obtains it can fetch that one object until it expires. CORS only controls browser access and does not replace authorization. Use HTTPS for the web, API, and storage public endpoint outside local development. Keep signed URLs out of application logs and analytics, and avoid sharing them. Immediate revocation of an issued URL requires changing the underlying signing permission or object; the short lifetime bounds ordinary exposure.

Set `STORAGE_PUBLIC_ENDPOINT` to the browser-reachable object storage or CDN HTTPS origin. Set `MINIO_CORS_ALLOWED_ORIGINS` to the exact web origins. The local defaults allow the user web on port 3000 and admin web on port 3001. Do not use `*` for production origins. Recreate the MinIO container after changing CORS environment variables, and rebuild the admin API after changing the manifest code. Existing data volumes do not need to be removed.

The current FFmpeg profile uses ordinary `.m3u8` and `.ts` entries. The manifest signer rejects external URLs, parent traversal, and URI-bearing HLS tags so that a future media profile cannot silently expose an unsigned key or alternate media. Extend the signer and its tests before enabling encryption keys, subtitles, or other URI-bearing tags. At larger scale, place a cache/CDN in front of object storage and configure its browser-facing origin; the API remains a control plane for manifest authorization and renewal.
